# Contributing to r8s

Thanks for your interest in contributing to r8s! This document describes how to
set up your development environment, our conventions, and what to expect from
the review process.

## Ways to Contribute

- **Report bugs** — open an issue using the bug report template
- **Suggest features** — open an issue using the feature request template
- **Improve documentation** — the docs site lives in `docs/`
- **Add components** — new operator-backed packages are always welcome
- **Fix bugs** — look for issues labeled `good first issue`

## Development Setup

**Requirements:** Node.js 20+ and npm 10+.

```bash
git clone https://github.com/berget-ai/r8s.git
cd r8s
npm install
npm run build   # build all packages
npm test        # run all tests
```

## Repository Structure

```
r8s/
├── packages/        # Publishable npm packages (@r8s/*)
│   ├── core/        # JSX factory, renderer, context, validation
│   ├── k8s-types/   # TypeScript types for Kubernetes resources
│   ├── cli/         # The `r8s` command-line tool
│   ├── recipes/     # High-level components (App, Database, Endpoint, ...)
│   └── ...          # One package per operator integration
├── examples/        # Runnable example projects
├── docs/            # r8s.berget.ai documentation site
└── k8s/             # This repo's own infrastructure (dogfooding)
```

## Making Changes

1. **Fork and branch.** Create a branch from `main`:
   `git checkout -b feat/my-change` or `fix/my-change`.

2. **Write tests.** Every package has tests in `__tests__/` using Vitest.
   New components must include tests covering rendering and operator
   declarations.

3. **Follow the conventions.**
   - Code is formatted with Prettier — run `npm run format` before committing.
   - Commits follow [Conventional Commits](https://www.conventionalcommits.org/):
     `feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:`.
     Scope optional, e.g. `feat(recipes): add Kafka component`.

4. **Open a pull request.** Fill in the PR template. PRs are reviewed within
   24 hours on weekdays.

5. **CI must be green.** The CI workflow builds all packages, runs all tests,
   typechecks, and verifies formatting.

## Adding a New Operator Package

1. Create `packages/my-operator/` following the structure of an existing
   package (e.g. `packages/redis/`).
2. Export your operator with `declareOperator()`.
3. Export components as TSX functions.
4. Add tests in `__tests__/`.
5. Add the package to the table in `README.md` and a page in `docs/`.

See `packages/redis` or `packages/prometheus` for minimal reference
implementations.

## Committing Generated Files

`k8s/rendered/manifest.yaml` is generated by CI — do not edit it by hand.
If your change affects rendered output, CI will commit the updated manifest
after merge.
